# Premium AI/Tech Shorts Pipeline — Architecture

Produces **1–2 premium 45–70s vertical videos/day** for TikTok, YouTube Shorts,
Facebook Reels, in the AI / Automation / Software / Programming niche.
Optimized for **watch time, retention, shares, saves, comments** — not upload volume.

Visual format: a **real-photo slideshow**, not AI-generated video. Each scene
is a real photo (via Tavily image search, matched to the actual event/company/
person when possible) or a relevant stock photo (Pexels fallback), animated
with a gentle Ken Burns zoom/pan — no Sora / AI video generation involved.

Two independent n8n workflows:

| File | Trigger | Purpose |
|---|---|---|
| `n8n_workflow_premium.json` | daily, 06:00 | Modules 1–10: research → script → storyboard → visuals → voice → subtitles → edit → SEO → publish |
| `n8n_workflow_analytics.json` | daily, 22:00 | Module 11: pulls YouTube stats, writes `learnings.json` that feeds back into Module 1 next run |

Both are generated by [generate_premium_workflow.py](generate_premium_workflow.py) — **edit that
script, not the JSON**, then re-run `.venv/bin/python generate_premium_workflow.py` to regenerate.
This keeps the pipeline maintainable (matches this repo's existing convention from `fix_workflow.py`).

## Module reference

### 1. Trend Research
- **Node group:** `Load Config & Learnings` → `Build Trend Search Query` → `Tavily Search (Trend)` (plain HTTP Request to the Tavily REST API) → `Parse Trend Search Results` → `Ollama Chat Model (Trend Synthesis)` + `Trend Synthesis Agent` → `Select Top Topic`.
- **Deterministic search-then-synthesize pattern** (see "Why not an agent+tool loop" below): a Code node builds one query string covering Google Trends, Google News, YouTube, Reddit, GitHub Trending, Product Hunt, OpenAI/Anthropic/Google AI blogs, a plain HTTP Request node calls Tavily directly, then a tool-free LLM call ranks the results.
- Returns **exactly 5** ranked candidates (virality, search interest, novelty, educational value, long-term search potential), selects the top one.
- Reads `learnings.json` (from Module 11) to avoid repeating recent topics and to lean toward what has performed well.
- **Fails loudly** (throws) if the synthesis step doesn't return valid JSON or the `candidates` field is missing — surfaces in n8n's execution log instead of silently producing garbage.

### 2. Deep Research
- Same deterministic pattern: `Build Deep Research Query` → `Tavily Search (Deep Research)` (`search_depth: advanced`) → `Parse Deep Research Results` → `Ollama Chat Model (Deep Synthesis)` + `Deep Research Synthesis Agent` collects facts, real examples, official docs, best practices from the search digest.
- `Validate Facts` **hard-fails the run** if fewer than 3 facts have a `source_url` — enforces "never invent information."

### Why not an agent+tool loop?
Modules 1-2 originally ran Tavily as an `ai_tool` inside an autonomous `@n8n/n8n-nodes-langchain.agent` (a ReAct loop where the LLM decides when/what to search). In real runs against a local Ollama model this was unreliable — it repeatedly hit **"Max iterations reached"** instead of producing a final answer, even after removing `format: "json"` from the driving model and raising `maxIterations`. Root cause: small local models are inconsistent at emitting the exact tool-call / final-answer format n8n's agent executor expects. The fix was architectural, not a parameter tweak: replace the autonomous tool loop with a **fixed** Code-node-built query → plain `httpRequest` call → tool-free LLM synthesis. This matches the pattern already reliable elsewhere in this pipeline (Script Writer, Storyboard, Visual Director, SEO all use a tool-free agent call and have not shown this failure).

### 3. Script Writer
- Structure enforced in the prompt: Hook → Problem → Explanation → Real Example → Key Takeaway → CTA.
- `Validate Script` hard-fails if `full_script` exceeds **170 words** or any required field is empty.

### 4. Storyboard
- `Storyboard Agent` splits the script into 5–8 scenes with all required fields (duration, narration, subtitle, visual_description, camera_motion, transition, emotion, text_overlay, animation_suggestion).
- `Normalize Storyboard` hard-fails unless total scene duration is **45–70 seconds**.

### 5. Visual Direction (most important module)
- Runs once per scene. No Sora / AI video generation - this is a **real-photo slideshow** format. Produces two search queries: `event_query` (specific real-world photo of the actual event/company/product/person mentioned in the narration, for Tavily image search) and `stock_query` (generic English description, Pexels fallback).
- The storyboard's `camera_motion` (push-in, pan-left, slow-zoom, etc. from Module 4) drives the Ken Burns zoom/pan applied to the photo at render time - Module 5 doesn't need to repeat it.

### 6/7/8 (per-scene loop)
One `splitInBatches` loop does all per-scene heavy lifting:
1. **Voice (Module 6):** POST to VietTTS (`viettts_server.py`, port 8002) — `speech_rate: 1.05` for an energetic, young, natural delivery. See [viettts_server.py](viettts_server.py).
2. **Real duration:** `ffprobe` measures the actual rendered audio length (TTS duration estimates drift, so subtitle/video timing is always locked to ground truth, not predicted duration).
3. **Subtitle cues (Module 7, partial):** splits the scene's subtitle text into ≤5-word phrases spread proportionally across the measured duration, tags one keyword per phrase for highlighting.
4. **Real photo (Module 8, partial):** `Tavily Image Search` looks for a real photo matching `event_query`; `Check Tavily Images` filters out logos/icons/favicons/Instagram CDN links; `Download Image (Tavily)` + `Validate Tavily Image` confirm it's a real, sufficiently-large JPEG/PNG/WEBP. If no valid Tavily image is found, `Pexels Image Search` (using `stock_query`) provides a stock-photo fallback. This exact pattern is reused from the already-proven `n8n_workflow_shorts.json` in this repo.
5. `Finalize Scene` pushes the assembled scene (audio path, image path, subtitle cues) into workflow static data, then loops back.

### 7/8 (assembly, after the loop)
- `Write storyboard.json` — durable per-video record (topic, script, scenes) for debugging/reproducibility.
- `Build Subtitles (ASS)` — generates a karaoke-style `.ass` file: base white text, keyword pops to accent color + scale-in (`\t` transform), max 2 lines, fades in/out — the "MrBeast-style" enjoyable-to-read subtitle look, never plain speech-to-text.
- `Build Render Script` — generates `render_video.sh` (ffmpeg): each scene photo is turned into a clip via `-loop 1 -i scene.jpg`, `scale+crop` to fill 1080x1920 (no letterboxing), then a Ken Burns `zoompan` matching the scene's `camera_motion`, trimmed to the real narration duration (`-t`). Scenes are joined with `xfade`/`acrossfade` transitions, background music mixed under narration with **sidechain-compression ducking**, `loudnorm` for consistent platform loudness, then subtitle burn-in (`ass=subtitles.ass`).
- `Execute Render Script (ffmpeg)` runs it.

### 9. SEO
- `SEO Agent` produces title, description, keywords, hashtags, and **platform-specific captions** (TikTok/Facebook/YouTube Shorts) — explicitly instructed to avoid clickbait.

### 10. Publishing
- `Upload To YouTube` — native `n8n-nodes-base.youTube` node, `privacyStatus: private` by default (flip to `public`/scheduled once you're ready to fully automate; recommended to start with manual review).
- `Publish To TikTok` / `Publish To Facebook Reels` — HTTP calls to the Content Posting API / Graph API Reels flow. **These require an approved developer app** (see API Integrations below) — they're wired with `continueOnFail: true` so a pending approval doesn't block YouTube publishing.
- `Log Publish Results` appends one line to `analytics/publish_log.jsonl`, which Module 11 consumes.

### 11. Analytics (independent workflow)
- Reads `publish_log.jsonl`, pulls YouTube Data API statistics + YouTube Analytics API retention/watch-time per video, appends to `analytics/analytics_store.jsonl`.
- `Compute Learnings` scores videos weighting **retention + shares + comments** above raw views (matching the stated priority: watch time/retention over vanity metrics), writes `analytics/learnings.json`.
- Module 1 of the main pipeline reads this file every run — closing the feedback loop without any manual analysis.

## API integrations

- **Tavily** — called directly via a plain `httpRequest` node (`POST https://api.tavily.com/search`, generic Header Auth `Authorization: Bearer <key>`), **not** the `@tavily/n8n-nodes-tavily` AI-tool node — see "Why not an agent+tool loop?" above for why.
- **Ollama** (default LLM) — local, no API cost, matches this repo's existing pattern (see `n8n_workflow_shorts.json`). Swap to OpenAI/Anthropic chat model nodes for meaningfully better script quality; only the `lmChat*` node needs to change, agents stay the same.
- **VietTTS** — reuses [viettts_server.py](viettts_server.py) already running on port 8002 in this repo (voice `infore`, tuned `speech_rate: 1.05`). See [memories/repo/viettts-server.md] for the jax/haiku compatibility patches already applied.
- **Tavily image search** — same `https://api.tavily.com/search` endpoint with `include_images: true`, used per-scene to find a real photo of the actual event/company/product/person (`event_query` from Module 5). Results are filtered to drop logos/icons/favicons/Instagram CDN links, then the downloaded file is validated (JPEG/PNG/WEBP magic bytes, >2KB) before use.
- **Pexels** — stock photo fallback (`GET /v1/search`, `orientation=portrait`) when Tavily has no usable event photo or it fails validation.
- **YouTube Data API v3** (`videos.insert`, thumbnails) + **YouTube Analytics API v2** (`reports.query`) — both via the same OAuth2 credential.
- **TikTok Content Posting API v2** (`/v2/post/publish/video/init/`) — requires TikTok Developer app approval (unaudited apps are capped to private/self-only posts); see TikTok's official onboarding docs.
- **Facebook Graph API Reels** (`/{page-id}/video_reels`, `upload_phase: start/transfer/finish`) — requires a Facebook Page + app with `publish_video` permission and Business verification.

## Error handling strategy

- Every LLM-output parsing step uses the same `parseAgentJson` helper (strips markdown fences, extracts the first `{...}` block) then hard-throws with a truncated preview of the bad output if parsing fails — errors surface immediately in the n8n execution rather than propagating malformed data downstream.
- Hard business-rule validations that **stop the run**: fact count ≥ 3 with sources (Module 2), script ≤ 170 words with all 6 structural parts (Module 3), total scene duration 45–70s (Module 4).
- Network calls that should **not** block the whole pipeline (`Publish To TikTok`, `Publish To Facebook Reels`, `Pexels Image Search`) are set `continueOnFail: true` combined with explicit `IF` branching (Tavily image validity) or independent parallel branches (publishing) so one platform/provider outage doesn't stop YouTube publishing or the whole video from finishing.
- Recommended addition once you have a notification channel: set the workflow's **Error Workflow** (Workflow Settings → Error Workflow) to a small workflow that posts to Slack/Telegram — not wired here since it depends on your notification credentials.
- `ffmpeg.log` is captured per-video (`exec 2>> ffmpeg.log` in `render_video.sh`) for post-mortem debugging, matching the convention already used in `n8n_workflow_shorts.json`.

## Extending into standalone sub-workflows

Each module's nodes are visually grouped with sticky notes and use only `main`/`ai_*` connections
that stay within the module, so any module can be lifted into its own workflow later:
1. Select the module's nodes in the n8n canvas → copy.
2. Paste into a new workflow, add a `Execute Workflow Trigger` as the entry point.
3. Replace the module's nodes in the main workflow with a single `Execute Workflow` node pointing at the new sub-workflow.

This wasn't done by default because sub-workflows require real workflow IDs that only exist once
imported into your n8n instance — doing it upfront would leave broken references until you rewire them anyway.

## Troubleshooting

### `Trend Research Agent` / `Deep Research Agent`: "Max iterations reached" (historical)
This was caused by running Tavily as an `ai_tool` inside an autonomous agent
(ReAct loop) with a local Ollama model. Tried in order: removing
`format: "json"` from the driving model, adding "stop calling the tool after
N times" instructions, raising `maxIterations` to 15 — the loop still
recurred. **Fixed by removing the agent+tool loop entirely**: Modules 1-2 now
build a fixed query in a Code node, call Tavily via a plain `httpRequest`
node, and synthesize the JSON with a tool-free LLM call (see "Why not an
agent+tool loop?" in the Module 1/2 reference above). This is a fully
deterministic pattern with no tool-call negotiation, so it can't loop.

If you customize Modules 1-2 further, avoid re-introducing an `ai_tool`
connection into `Trend Synthesis Agent` / `Deep Research Synthesis Agent`
unless you've verified your chosen model reliably supports n8n's tool-calling
format (larger hosted models like GPT-4o/Claude are far more reliable at this
than small local Ollama models).

## Setup checklist

1. `python3 generate_premium_workflow.py` to (re)generate the two JSON files.
2. In n8n: **Import from File** both `n8n_workflow_premium.json` and `n8n_workflow_analytics.json`.
3. Reselect every credential flagged `REPLACE_ME` (Ollama, Tavily, Pexels, YouTube, TikTok, Facebook).
4. Set `AI_SHORTS_BASE_DIR` and confirm `viettts_server.py` is running on port 8002 (`.venv/bin/python viettts_server.py`).
5. Drop a royalty-free `assets/bgm/default.mp3` and `assets/sfx/whoosh.wav` into `AI_SHORTS_BASE_DIR/assets/`.
6. Run the main workflow once manually, inspect `<videoId>/final_video.mp4` and `ffmpeg.log` before enabling the schedule trigger.
7. Leave `Upload To YouTube` at `privacyStatus: private` until you've reviewed a few outputs, then flip to `public`.
